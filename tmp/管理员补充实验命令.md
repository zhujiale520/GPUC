> 复现命令和仍未授权的 NVMe 边界。

## 1. 已不需要管理员处理：Vdbench

Vdbench 5.04.07 与项目私有 Temurin Java 8 已安装在被 Git 忽略的
`third_party/manual/`，官方自检和 50 组正式样本均已完成。不要把 Oracle 许可包

## 2. DRAM bandwidth、LLC miss 与 CPU package 能耗

> V100 512 MiB 同吞吐 DRAM bandwidth 已完成。RTX 4090 的 128/512 MiB
> PCM 也各完成三场景五轮，但包裹执行时双方未同时达到请求吞吐，只作为饱和边界。
> 结果见 `results/final/pcm_dram_*rtx4090*`；下面保留为复现命令。

先在宿主机安装工具并开放本次实验所需计数器：

```bash
sudo apt update
sudo apt install -y build-essential cmake git linux-tools-common linux-tools-generic msr-tools
sudo modprobe msr
sudo sysctl kernel.perf_event_paranoid=-1
sudo sysctl kernel.kptr_restrict=0
```

自定义 `5.15.0` 内核可能没有同名 Ubuntu `linux-tools` 包。先检查：

```bash
perf version
perf stat -e cycles,instructions,cache-references,cache-misses -- sleep 1
ls -l /dev/cpu/0/msr
```

Intel PCM 已从官方仓库下载并成功编译，无需重复 clone/build：

```bash
git -C third_party/manual/pcm rev-parse HEAD
# 本次固定版本：4246ea47f27c471bcc8484c065886f31f449933e
third_party/manual/pcm/build/bin/pcm-memory --help
```

先验证计数器是否可用：

```bash
sudo third_party/manual/pcm/build/bin/pcm-memory 1
sudo third_party/manual/pcm/build/bin/pcm 1
sudo third_party/manual/pcm/build/bin/pcm-power 1
```

正式 DRAM 实验已经封装为一条命令。脚本会让 PCM 分别包裹 Baseline、CPU LZ4
和 GPU LZ4，轮换顺序并各运行五次，输出逐轮 CSV、95% CI 和全部 PCM 原始文件：

```bash
sudo env \
  GPUC_RESULT_DIR="$PWD/results/local/pcm_dram_v100_20260730" \
  GPUC_RUNTIME=10 GPUC_REPEATS=5 GPUC_TARGET_MIB_S=4096 \
  GPUC_WORKSET_MIB=512 GPUC_BATCH_BLOCKS=128 \
  GPUC_DECOMP_CPU=0 GPUC_WORKER_CPU=0 \
  bash tests/pcm_dram_offload.sh
```

实验结束后恢复宿主机安全策略：

```bash
sudo sysctl kernel.perf_event_paranoid=2
sudo sysctl kernel.kptr_restrict=1
```

`pcm-memory` 可以补 IMC 读写带宽，`perf stat` 可以补 LLC/cache miss；
`pcm-power` 能否读取 package 能耗取决于该 Xeon、BIOS 和 MSR 暴露情况。若仍显示
不支持，则必须使用 BMC/IPMI 或外部功率计，单纯安装软件不能制造整机功耗数据。

## 3. NVMe

当前 `lsblk` 显示 `nvme0n1` 为 ext4，但受限会话没有 `/dev/nvme0n1` 节点。
先在宿主机做只读核验，**不要运行 mkfs，不要格式化设备**：

```bash
sudo apt install -y smartmontools
sudo lsblk -f /dev/nvme0n1
sudo blkid /dev/nvme0n1
findmnt -S /dev/nvme0n1
sudo smartctl -a /dev/nvme0n1
```

若确认该 ext4 卷允许用于比赛、当前未挂载且其中数据可保留，挂载并只创建独立
测试目录：

```bash
sudo mkdir -p /mnt/gpuc_nvme
sudo mount -o noatime /dev/nvme0n1 /mnt/gpuc_nvme
sudo install -d -o ubuntu -g ubuntu /mnt/gpuc_nvme/gpuc-bench
df -hT /mnt/gpuc_nvme
```

随后运行安全入口；它会拒绝非 NVMe 路径，且只删除自己创建的临时目录：

```bash
GPUC_NVME_DIR=/mnt/gpuc_nvme/gpuc-bench \
GPUC_RESULT_DIR="$PWD/results/local/nvme_v100_20260730" \
GPUC_SIZE=512M GPUC_RUNTIME=10 GPUC_REPEATS=5 \
bash tests/nvme_formal.sh
```

## 4. Btrfs、ZFS 与 device-mapper

RTX 4090 已使用脚本自建并验证 backing file 的 loop device 完成 Btrfs 合成暖缓存
和真实 corpus 文件级失效两组，各 30/30、SHA 一致、zstd extent 生效。脚本不会
格式化物理 NVMe；结果仍不能当作介质性能。ZFS 与 DM 后端仍未实现。

软件可以安装：

```bash
sudo apt update
sudo apt install -y btrfs-progs zfsutils-linux thin-provisioning-tools
sudo modprobe loop
sudo modprobe dm_mod
```

但横向实验还需要一个明确可销毁的空闲分区或位于 NVMe 测试目录中的 loop 镜像，
并会执行 `mkfs`。在管理员明确指定该**一次性目标**之前，只做能力审计：

```bash
sudo losetup -f
sudo dmsetup version
btrfs version
zfs version
zpool version
```

不要对 `/dev/nvme0n1` 本身执行 `mkfs.btrfs`、`zpool create` 或 `dmsetup remove`。

## 5. 软件无法补齐的硬件项

- 鲲鹏 920/AArch64：必须在对应 CPU 硬件实测；
- 赛题指定 RTX 3060/4060/5060：RTX 4090 已完成补充实测，但不能替代指定型号；
- 整机能效：没有可用 RAPL/PCM 时必须用 IPMI/BMC 或外部功率计；
- NVMe：设备节点和挂载必须由宿主机/容器管理员真实提供。
