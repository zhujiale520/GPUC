# Vdbench 5.04.07 V100 正式结果

## 方法

- 设备环境：Tesla V100-SXM2-32GB，结果文件所在卷为 SATA/ext4；
- 数据：256 MiB、逐 4 KiB 页变化的确定性非零可压缩 pattern；
- Vdbench：5.04.07，4 线程，2 秒 warmup、10 秒计时、每组五轮；
- I/O：所有场景统一 buffered warm-cache；本目录不是 NVMe 成绩；
- 读取：128 KiB 顺序读、4 KiB 随机读；
- 写入：70:30 随机混合读写只比较可写的 Baseline 与 Hook RAW；
- 校验：50/50 样本通过，文件状态正确，逻辑 SHA-256 全部一致。

## 边界

Baseline/RAW 的极高数值主要反映页缓存和内存复制，不代表 SATA 或 NVMe 介质
带宽。压缩路径尤其是共享 fd 的随机读明显较慢：修复以互斥保证同一 open file
description 的 read-ahead/cache 正确性，代价是共享 fd 读取序列化。该结果用于
暴露当前架构短板，不能包装成 GPU 文件读取加速。

Oracle Vdbench 和项目私有 Java 未复制到本结果目录，也不随仓库再分发。
